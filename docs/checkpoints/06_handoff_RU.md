## Как объяснить устройство

**Путь запроса.** Браузер отправляет название сборки, бюджет и CSRF-токен на сервер. FastAPI определяет вошедшего пользователя, проверяет форму и токен. SQLite сохраняет строку с ID владельца. Сервер отвечает 303 и браузер открывает страницу сборки. Обновление страницы повторяет чтение. Jinja подставляет прочитанные значения в HTML.

**Таблицы.** `categories` — категории, `components` — детали, `builds` — сборки, `build_items` — выбранные детали и их количество. Одна сборка содержит много строк `build_items`. Одна деталь может встречаться в нескольких сборках. В каждой строке связующей таблицы два внешних ключа: на сборку и деталь. Пара уникальна. При удалении сборки SQLite автоматически удаляет связанные позиции, а деталь из каталога сохраняется. Деталь, которая уже используется, удалить нельзя. `users` хранит пользователей, `login_sessions` — хеши токенов и срок действия.

**Права.** Student и Admin могут работать со своими сборками. Admin также может менять каталог. Запрос сборки содержит её ID и ID владельца. Если открыть чужую сборку, сервер выдаст 404.

**Деньги и совместимость.** Цены хранятся в центах. Три детали дают 19 000 + 13 000 + 5 500 = 37 500 центов. Проверки сверяют сокет CPU и поколение памяти с материнской платой. Цена учебная, совместимость охватывает только эти две проверки.

**Если просят код.** Ищи `create_build`, `owned_build`, `build_detail` в `app.py`. В `db.py` покажи `connection` и `PRAGMA foreign_keys = ON`. В `database/schema.sql` покажи `build_items`, `ON DELETE CASCADE`, `ON DELETE RESTRICT` и `UNIQUE`. В `tests/test_app.py` покажи CRUD, роли и ownership. Для чтения в браузере используй ссылку на исходники из стартовой страницы.

**Про вклад.** Говори только о действиях, которые можешь подтвердить. Существенная помощь AI была в прототипе, редизайне, документации и подготовке проверок. Финальная защита требует участия обоих студентов.
